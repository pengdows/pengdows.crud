# UUIDv7 Surrogate Keys (`Uuid7Optimized`)

`Uuid7Optimized` (`pengdows.crud/Uuid7Optimized.cs`) is a production-ready, RFC 9562-compliant UUIDv7 generator marketed as a headline feature in `README.md`/`CLAUDE.md`/`llms.txt`, but until this doc existed, external documentation was a single bare `Uuid7Optimized.NewUuid7()` call in the quick-start guide. The class itself is thoroughly documented in its own XML comments — this doc surfaces that detail externally rather than re-deriving it.

## Basic usage

```csharp
Guid id = Uuid7Optimized.NewUuid7();
```

Time-sortable for stores that compare the UUID byte pattern directly (PostgreSQL, MySQL, SQLite). **Not automatically true for SQL Server's `uniqueidentifier`**, whose comparison semantics don't sort by RFC byte order — pengdows.crud deliberately does not work around this with an implicit byte permutation.

## Monotonicity scope: per-thread, not process-wide

This is the detail most likely to surprise someone reasoning about ordering guarantees: **monotonic ordering is per-thread only.** Two UUIDs generated by different threads within the same millisecond are *not* guaranteed to sort in call order — only same-thread, same-millisecond generation is strictly increasing. A shared global epoch does coordinate the millisecond timestamp floor across threads (no thread will ever pick an earlier millisecond than one already observed process-wide), but it does not coordinate the intra-millisecond sequence field between threads. Not guaranteed across machines at all.

## Throughput and backpressure

Each thread can generate up to 4096 IDs/ms (a 12-bit counter) independently of other threads. Exceeding that within one thread makes `NewUuid7()` (and `NewUuid7Bytes`/`NewUuid7RfcBytes`) **block** until the next millisecond (bounded spin, then `Thread.Sleep(SleepMs)`).

`TryNewUuid7(out Guid result)` never blocks — it returns `false` on counter overflow, for latency-sensitive call sites that would rather skip/retry than wait. This is the only non-blocking path: `Uuid7Options.FailFastOnBurst` is accepted and stored by `Configure`, but no generation method currently consults it, so setting it does not make `NewUuid7()` throw or return early.

## Clock drift handling

On a backward clock jump, the generator never resyncs to the observed wall-clock value — both branches below use a held-back logical timestamp instead:
- **Small drift** (≤ `Uuid7Options.MaxNegativeSkewMs`, default 5ms): pins to the thread's own last timestamp.
- **Large drift**: adopts the cross-thread global epoch instead, if it's further ahead.

Blocking on counter exhaustion during a large backward clock jump is intentionally unbounded in wall-clock duration (only the spin/sleep cadence is bounded) — trading worst-case latency for strict per-thread ordering. Use `TryNewUuid7` if that trade-off is wrong for your workload.

## Configuring for your deployment

```csharp
Uuid7Optimized.Configure(new Uuid7Options(
    Mode: Uuid7ClockMode.PtpSynced,
    MaxNegativeSkewMs: 1,
    MaxSpinCount: 64));
```

| `Uuid7ClockMode` | Accuracy assumption | Behavior | Use when |
|---|---|---|---|
| `PtpSynced` | ±0.1–1.0ms | Tight skew tolerance, shorter spin waits | PTP-disciplined clusters (EKS Nitro, on-prem PTP) |
| `NtpSynced` (default) | ±1–10ms | Conservative skew tolerance, longer spin waits, blocks on burst | Most cloud environments with ordinary NTP |
| `SingleInstance` | N/A | Generous skew tolerance, no cross-node ordering concerns | Single-writer services, embedded systems |

`Uuid7Options` fields: `Mode`, `MaxNegativeSkewMs` (default 5), `MaxSpinCount` (default 128, spin-wait cycles before sleeping on counter overflow), `SleepMs` (default 1), `FailFastOnBurst` (default `false`; currently not consulted — see above).

If you pass only `Mode` (every other field left at its record default), `Configure` substitutes that mode's own defaults. If you pass custom values, they are clamped per mode: `PtpSynced` caps `MaxNegativeSkewMs` at 1 and `MaxSpinCount` at 64; `NtpSynced` raises them to at least 5 and 128; `SingleInstance` uses them as given.

## Other entry points

- `NewUuid7Bytes(Span<byte> dest)` / `NewUuid7RfcBytes(Span<byte> dest)` — write directly into a byte buffer instead of allocating a `Guid`.
- `GetThreadState()` / `GetGlobalEpoch()` — introspection for tests/diagnostics, not typically needed in application code.
