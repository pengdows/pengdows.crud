# Type testing and verification worklist

Everything that still needs testing or verification, by database and type. Generated by
`tools/datatype-probe/gen_verification_worklist.py` from `docs/datatype-unified-crossref.md` (what each database documents),
`tools/datatype-probe/reconciliation.csv` (concept to probe type), `TypeFidelityCells.cs` (the cells the fidelity test has) and
`TypeFidelityDeclarations.cs` (what each database tests or refuses). Do not edit by hand: close an item in its source and re-run it.

This is a worklist, not a verdict. A probe type marked *[override]* is the generator's judgement of which cell covers a concept
that `reconciliation.csv` never linked (`OVERRIDES` in `audit_gaps.py`), so a row may disappear once that mapping is confirmed.
A cell is *tested* when the database declares a column for its probe type and the fidelity test round-trips it on both frameworks.

## Type conversions

The standard is a conversion test and a fidelity test for every type on every database. Fidelity is what the rest of this document
tracks. For conversions, what exists:

- **Unit, provider-independent:** `TypeCoercionCombinatorialMatrixTests` and its siblings convert a runtime value of one type to a target
  type (numeric widening and narrowing, string and numeric, and so on), with no database involved.
- **fakeDb, every sample on every emulated database:** `FakeDbSampleRoundTripTests` writes each CLR type sample through the library's own
  write path and reads it back on every `SupportedDatabase` product (about 13,000 cases). It proves the library's write and read are inverses
  per product; what a real server does with the stored value is the live matrix's job. A database's own unreadable types are asserted as the
  typed refusal (DuckDB's GEOMETRY).
- **Live, a fixed set of columns:** `TypeHydrationTests` reads one entity with typical, zero/null and boundary rows on every database;
  `TypeRoundTripMatrixTests` and the fidelity test read each column back as its natural .NET type.
- **Not found:** a live matrix of each database's column type read as each of the other .NET types it can map to (an INTEGER column as
  long, decimal, double, string or an enum; a TEXT column as a number or a date; a NUMERIC as a float), checked per database. Until one
  exists, a conversion that works in the unit matrix is not shown to work on any given database's reader. This is the largest unverified
  area and has no per-database row below.
