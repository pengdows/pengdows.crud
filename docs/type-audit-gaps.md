# Type audit: documented-supported types without a passing fidelity test

Generated by `tools/datatype-probe/audit_gaps.py` from `docs/datatype-unified-crossref.md` (what each database documents),
`tools/datatype-probe/reconciliation.csv` (concept to probe type) and `TypeFidelityDeclarations.cs` (what is tested or refused).
Do not edit by hand: change the sources and re-run it.

**Supported** is a cell the workbook marks N (native) or A (alias). **Tested**: the database declares a native column for the concept's
probe type, so the fidelity test round-trips it (a type that round-trips only through a wider column is Gap A). **Recorded**: a refusal with a stated verdict (by design, server, upstream, or a probe refusal validated against the vendor's documentation).
**Gap A**: supported, but the only record is `refused: <server text>`, meaning the probe found no accepted spelling; the type may be
untested because its working spelling was never a candidate. **Gap B**: supported, but the concept has no probe type or no fidelity cell, so nothing tests it.
V, E, R and ? cells are counted, not listed. A probe type marked *[override]* is this audit's judgement of which cell covers a
concept that `reconciliation.csv` never linked (`OVERRIDES` in the script), not data.
